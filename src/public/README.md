# Prompt Studio · 提示词工作台

一句话输入 → 一份可以直接交付的高级提示词。带模型接口（OpenAI 兼容），零依赖，本地运行。

```bash
cd prompt-studio
node server.mjs
# 会自动打开 http://127.0.0.1:5178
```

Windows 上也可以直接双击 `run.cmd`。**这个窗口要一直开着**：它就是服务本身，关掉之后页面上的「生成」就会报连不上本地服务（重新运行即可，页面会自己恢复）。

需要 Node 18+（本机是 v22）。没有任何 npm 依赖，不需要 `npm install`。

---

## 它做了什么

普通「提示词生成器」是把你的话丢给模型说一句「帮我优化」。这个工作台是把提示词工程拆成四步，并且把每一步的结果摊开给你看：

| 阶段 | 做什么 |
| --- | --- |
| 01 解析需求 | 读出真实意图、挑出原始请求的缺口，并把缺口变成沟通里要问的问题 |
| 02 撰写提示词 | 撰写正式提示词：目标 / 角色 / 已知输入 / 步骤 / 规则 / 输出格式 / 自检 / 变量 |
| 03 严格评审 | 按十个维度打分（具体性、结构、约束、输出契约、贴合度、运行时匹配、清晰度、可复用性、正面表述、无废话指令），列出 blocker / major / minor 问题 |
| 04 按意见修订 | 把问题逐条改掉；带停止规则地迭代，最终保留得分最高的那一版 |

深度模式打开 = 跑完整四步，而且是**带停止规则的迭代**：评审 → 得不到分就改写 → 复评，直到达标或改不动为止（详见「迭代与停止规则」）。关闭 = 只跑 01+02，快一半。

### 生成前先沟通（重点）

点「开始沟通」后**不生成提示词**，而是进入多轮对话：

1. AI 每轮只问 **1–3 个最关键的问题**（使用场景/平台、目标受众、风格语气篇幅、输出格式、参考样例、硬性约束…），并给出可点的候选答案；
2. 你回答（或点「这轮跳过，你按默认决定」）→ AI 继续追问，**最多 4 轮**；
3. 每一轮 AI 都会返回一份「**已收集到的信息**」快照，界面实时显示，并且会被原样打包进最终提示词；
4. 当 AI 判断信息足够时，会明确写出「**信息已收集完毕，可以点击生成**」，此时才点「生成提示词」——
   **沟通阶段不会触发任何生成动作**，生成永远由你主动点击。

其他细节：

- 沟通可以**单独指定用哪个模型**（右上角下拉），也可以和生成用同一个；
- 想省事可以点「跳过沟通，直接生成」，此时回到上一版的「缺口选项 + 确定」快速补全；
- 沟通记录与生成结果**关联保存**：生成完自动存一条「历史会话」，含需求、全部对话、信息快照、最终提示词、用的哪个模型，随时回看或重载。

### 两套元提示词，都能改

左栏「元提示词模板」里可以编辑两套：

| 模板 | 作用 |
| --- | --- |
| ① 沟通提问用 | 决定 AI 怎么找缺口、怎么提问、什么时候收尾（含"不要为凑轮次而提问"） |
| ② 生成提示词用 | 决定最终提示词怎么写（正/负面表述、去废话指令、领先词、输出契约等） |

改完点「保存模板」即生效，随时可「恢复默认」。

### 迭代与停止规则

深度模式不是固定改一轮，而是循环，命中任一条件就收手：

| 停止条件 | 说明 |
| --- | --- |
| 达到 9.0 分 | 已经够好，再改只是换措辞 |
| 两轮之间提升不足 0.3 分 | 收益太低（回退也算），继续投入不划算 |
| 评委判定可以停 | 模型在评审结果里给出 `stopRecommendation` 与理由 |
| 达到 3 轮上限 | 兜底 |

而且**最终保留得分最高的那一版**，不是最后一版 —— 如果改完反而更差，会自动回退，并在自评页的「迭代记录」里逐轮列出得分与停止原因。这套设计参考了 `linshenkx/prompt-optimizer` 的 stop signals / bestScore / acceptedRound。

### 输入与输出

左侧只需要一句话：

> 帮我给新品发布会写一封邀请函，发给三年以上的老客户

右侧得到的是这种可以直接粘贴使用的成品：

```markdown
# 目标
写一封发给三年以上老客户的新品发布会邀请函，读完后对方知道时间、地点、亮点，并且愿意点开报名链接。

# 角色
你是品牌方的主理人，写给认识多年的老朋友。语气克制、平等、具体，不谄媚、不堆形容词、
不使用「重磅」「盛宴」这类营销词。

# 已知输入
- 活动名称：{{event_name}}
- 时间：{{date}}
...
# 约束
- 必须：包含活动名称、时间、地点、报名方式四项信息。
- 必须：正文控制在 300 字以内。
- 不要：编造未提供的嘉宾、价格、赠品信息。
...
# 自检
- 四项必要信息齐全吗？
- 有没有出现没有依据的承诺？
```

所有可变内容会被抽成 `{{变量}}`，在「变量」标签页里逐个列出，点一下即可复制。

## 模型接口管理

左边第 03 块是「模型接口」，支持任意多个接口的增删改查、启停与连接测试。

| 字段 | 说明 |
| --- | --- |
| 名称 | 自定义别名，例如 `GPT-4o` / `通义千问` |
| 接口协议 | **OpenAI 兼容**（DeepSeek/Kimi/通义/OpenRouter/本地 Ollama…）、**Anthropic**（Claude 官方：`x-api-key` + `anthropic-version`）、**自定义模板**（自己写 URL 与请求体模板） |
| Base URL | 例如 `https://api.deepseek.com/v1`，也可以直接填完整的 `.../chat/completions` |
| 模型 ID | 例如 `deepseek-flash` |
| API Key | **加密保存**，页面里只显示掩码 |
| 额外参数 | temperature / max tokens /（OpenAI 兼容还可选 chat 或 responses 风格） |
| 备注 | 用途、价格、谁给的额度 |

### 密钥怎么存的

- 配置写在安装目录下的 `data/profiles.json`；**API Key 单独加密**，不和配置混在一起。
- Windows 上用 **DPAPI**（`ProtectedData`，绑定当前 Windows 账户）：文件拷到别的机器或别的账户都解不开。换系统时会解不开，重新填一次即可。
- **密钥永远不会回传给浏览器**：列表接口只给 `hasKey` 与 `sk-…1234` 这样的掩码，出网请求由本地服务注入密钥。
- 首次打开时，如果检测到环境变量里有 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`，会自动铺两条对应接口（列表里标「环境变量」），不用手填就能直接用。

### 连接测试

每个接口都有「测试」按钮，发一个最小请求，记录耗时与错误文本，并写回列表。

## 生成模式：单模型 / 多模型对比

顶部工具栏可以切换：

- **单模型**：选一个接口，走完整的四步流水线（含深度模式的迭代停止规则）。
- **对比**：勾选 2 个以上接口，**先用第一个模型解析需求，再让每个模型并行撰写同一份需求**（同一份解析 = 公平比较写作能力），同屏并排显示。

每一列会标明 **哪个模型 / 耗时 / token 消耗**（读接口返回的真实 `usage`）。每列还能：

- **用这版** —— 把它设为主版本，回到单模型模式用「变量 / 自评」继续处理
- **复制** —— 单独复制这一版

**失败是隔离的**：某个接口挂了（地址错、Key 错、被墙），只影响它那一列，显示中文错误，其它列照常出字。并发上限建议 3~4 个模型。

## 不填 Key 也能用

不配置 Key 时走内置规则模式：按关键词判断任务类型（写作 / 代码 / 数据 / 图像 / Agent / 视频），套结构化的提示词骨架，加约束和自检，并且逐字打出结果。它是离线可用的下限保障，不是替代品——填上 Key 之后才会做真正的改写和自评。

## 目录结构

```
prompt-studio/
├── server.mjs                    零依赖本地服务：静态文件 + 接口配置 REST + 按 id 转发 + DPAPI 加密
├── README.md
├── data/
│   └── profiles.json             模型接口配置（密钥字段是 DPAPI 密文）
└── public/
    ├── index.html                输入台 + 输出台
    ├── styles.css                制图台风格：冷色蓝本 + 稿纸网格 + 红色批注线
    └── js/
        ├── adapters.mjs          协议适配层：OpenAI 兼容 / Anthropic / 自定义（服务端与浏览器共用）
        ├── profiles.js           接口管理：列表、表单、启停、测试、选择
        ├── prompt-engine.mjs     提示词引擎：四阶段元提示词 + 离线规则模式
        └── app.js                界面、单模型/对比编排、流式渲染、停止规则、变量填充
```

服务端只是个「转发 + 静态托管」的角色，编排逻辑都在浏览器侧，所以也可以直接用 `file://` 打开 `public/index.html`（此时会直连模型接口，可能被浏览器跨域策略拦截，推荐还是用 `node server.mjs`）。

## 优化记录

- **v6 · 2026-10-13**：界面精简 + 多模型改选项卡 + 导出文档
  1. 侧栏精简：删掉示例标签、整个「目标运行时」模块、整个「补充要求」模块；主界面只剩「你的需求 / 详细程度 / 模型接口」三块；
  2. 「详细程度」从按钮组改成下拉；「输出语言」固定中文并从界面移除；
  3. 移除中间栏的「自评」标签页，评分压缩成工具栏徽标（悬停看详情）；
  4. 多模型**不再并排**，改成**选项卡**：点模型名切换查看，标签上带耗时/token 与成功失败状态；
  5. 新增**导出为文档**：把需求、沟通补充、提示词、变量整理成一份 Markdown 文档，走系统「另存为」（File System Access API）选择保存位置，不支持时回退为下载。

- **v5 · 2026-10-12**：生成前的**多轮沟通补充**
  1. 「开始沟通 → 逐轮提问 → 信息够了 → 你点生成」的两段式流程，沟通阶段不消耗生成动作；
  2. 每轮 1–3 个问题 + 可点候选 + 「这轮跳过」，最多 4 轮，模型自主判断何时收尾；
  3. 每轮产出**信息快照**（facts），实时展示并打包进最终提示词；
  4. **两套元提示词**（沟通提问 / 生成写作）都可在界面上编辑与恢复默认；
  5. **历史会话**：需求 + 全部对话 + 信息快照 + 生成结果关联保存，可回看可重载；
  6. 沟通后不再显示旧的一次性缺口清单（避免两套澄清逻辑打架），跳过沟通时仍然保留它。

- **v4 · 2026-10-12**：多模型能力
  1. **模型接口管理**：多接口增删改查、启用/禁用、连接测试、协议可选（OpenAI 兼容 / Anthropic / 自定义）；配置与密钥分离，密钥用 Windows DPAPI 加密，页面只显示掩码，**密钥永不回传浏览器**；
  2. **协议适配层**：新增 `adapters.mjs`，服务端与浏览器共用同一份，差异（认证头、`system` 位置、流式事件、usage 字段）全部收敛在适配器里，新增一家模型 = 加一个 adapter；
  3. **多模型并发对比**：勾选多个接口后并行调用、同屏并排、逐列标明模型/耗时/tokens，失败隔离；
  4. **环境变量回退**：首次启动自动按环境变量铺种接口，老用户不用重新填 Key；
  5. 修掉一个真实的性能 bug：`<head>` 里的 Google Fonts 阻塞样式表会把整个应用的启动拖到 **20.6 秒**，改成异步加载后降到 **0.2 秒**。

- **v3 · 2026-10-12**：借鉴 `prompt-optimizer` 与 `writing-for-agents` 做了三项增强 ——
  1. 深度模式从「固定改一轮」升级为**带停止规则的迭代**（达标 / 收益不足 / 评委判定 / 轮数上限），并**保留最高分版本**、自动回退、逐轮展示得分；
  2. 评审 rubric 从 8 轴扩到 10 轴，新增 **正面表述**（约束是否写成了目标行为而不是禁令）与 **无废话指令**（是否含模型默认就会遵守的句子）；
  3. 撰写规则同步更新：优先正面表述、删掉无操作指令、用领先词锚定行为、每个步骤带可核查的完成标准；
  4. 变量页从「只列出」升级为**可填写并实时生成最终提示词**，可一键复制。

## 常见问题

**页面报「连不上本地服务」/ 浏览器控制台报 `Failed to fetch`？**
页面还在，但后台的 `node server.mjs` 已经退出了 —— 这个服务的生命周期就是那个终端窗口，关掉窗口服务就没了。重新执行 `node server.mjs`（或双击 `run.cmd`），然后点页面右上角的「重新连接」。页面顶部会实时显示服务状态：`本地服务已断开` 就说明是这个问题。

**填了 Key 还是提示连接失败？**
先点「测试连接」。若报「无法连接到模型服务」，通常是 Base URL 写错（注意有的服务需要带 `/v1`），或者当前网络访问不到该服务。

**报 `The supported API model names are ...`？**
模型名和服务商对不上。DeepSeek 现在只接受 `deepseek-flash` / `deepseek-v4-pro`（旧的 `deepseek-chat` 已不在列表里），把「模型名」改掉即可。

**用 Responses 风格时报 400？**
说明该服务只支持 Chat Completions，把「接口风格」切回去即可。

**内容太长/太短？**
调「详细程度」（精简 / 标准 / 详尽），它直接控制最终提示词的篇幅预算。

**想换目标场景？**
「目标运行时」有七种：通用对话 / 写作 / 代码 / Agent 工具调用 / 图像生成 / 数据与结构化输出 / 视频分镜。不同的运行时会让同一个需求写出完全不同的提示词。
