## 三、关键实现说明

### 1. 深度模式：真实二轮

新增了独立的审稿请求：

- 第一轮：按原始需求和已确认信息产出初稿。
- 第二轮：把初稿交给审稿提示词，要求删除冲突规则、重复段落和不可执行约束。
- 第二轮失败：保留第一轮初稿，并在结果页显示“审阅失败，已保留初稿”。
- 离线规则：仍然无法发起网络二轮，但界面会明确说明“离线引擎已追加自查要求”，不再宣称模型修订。

结果页文案也按真实流程变化：

- 模型深度模式成功：`4 / 4 步全部完成 · 深度模式：已完成自评与修订`
- 模型深度模式审阅失败：`深度模式：审阅失败，已保留初稿`
- 离线深度模式：`深度模式：离线引擎已追加自查要求`
- 普通模型/离线生成：`3 / 3 步全部完成`

### 2. Prompt 去重与冲突消除

修改了三处模板逻辑：

- `目标` 小节保留一次需求原文。
- `输入` / `需求与对象` 不再再次粘贴原始需求。
- 执行步骤从“先用一句话复述目标”改为“核对目标、对象与交付边界；发现冲突时只列必须确认的问题”。
- 约束改为“不要在正文重复需求原文”，与执行步骤保持一致。
- 模型请求和审稿请求都明确要求：需求原文只用于理解，不要贴回正文。

实测生成结果：

```text

hasNoRestate: true
需求原文出现次数: 1
```

### 3. 320px 响应式

调整了 `fitPanel()` 的高度计算：

- 不再强制面板至少 240px 高。
- 面板最大高度改为基于 `composer` 顶部、固定导航底部和视口余量计算。

新增 360px 以下紧凑布局：

- 品牌标题不换行，超出时省略。
- “添加模型”和状态标签压缩。
- 单模型 / 多模型按钮不折行。
- 底部功能按钮换行，第三个按钮不再被裁切。

即面板已从导航下方开始，页面无横向溢出，第三个按钮完整可见。

### 4. 可访问性

- 分段选择组增加 `role="group"` 与 `aria-label`。
- 所有分段按钮增加 `aria-pressed="true/false"`，切换时同步更新。
- 生成模式的单模型/多模型按钮也加入同样的可访问状态。
- `armConfirm()` 增加可选的确认态 `aria-label`，并保存/恢复原标签与 title。
- 历史删除、历史清空、模型删除均传入明确确认标签。

## 五、行为变化与注意事项

1. **深度模式会变慢**：模型模式从一次请求变成两次请求，等待时间和 token 消耗会增加。这是“自评并修订”的真实成本；如果更看重速度，可以保持开关关闭。
2. **离线深度模式仍是单轮**：离线规则无法调用模型审稿，因此只会在提示词里追加自查要求。界面已经明确写出这一点，不再宣称“已修订”。
3. **审阅失败不丢初稿**：第二轮失败时保留第一轮可用结果，结果页会显示黄色提示。
4. **多模型模式会使用所有可用模型**：底部选择器不再暗示只生成选中的单个模型。
5. **320px 功能面板内容需要内部滚动**：为了避免遮挡输入区和导航，面板高度优先保证位置正确，内容较长时在面板内部滚动。

## 七、提示词可执行性改进

新增了让提示词“拿到就能开工”的固定结构：

- `执行契约`：明确直接开工、最多 3 个澄清问题和假设标注规则。
- `必须覆盖`：从需求中识别用户画像、核心流程、优先级、验收标准、测试等必填项。
- `输出格式`：固定为“最终交付物 → 假设与待确认 → 验收自检”。
- 领域格式：前端/后端给出文件树、代码、命令和测试；产品给出 PRD 章节；数据给出指标口径和 SQL；客服/运营给出可直接使用的话术与模板。
- 评分增加对 `执行契约`、`输出格式` 的检查，缺失时会给出改进建议。

用真实 DeepSeek 模型测试后，模型完整输出了用户画像、核心流程、功能优先级、验收标准、假设和自检，详见：[模型输出能力测试说明.md](模型输出能力测试说明.md)。

## 八、动态多轮追问

“先沟通再生成”不再固定套用同一份六问问卷，而是：

1. 用户发射需求后，模型读取需求并生成 4–6 个针对该任务的追问。
2. 每个追问包含问题、解释、影响、可点击选项和多选标记。
3. 用户逐轮选择或填写补充，可回上一轮、跳过当前轮或跳过剩余轮。
4. 所有动态问答写入 `沟通补充`，并随模型请求一起发送。
5. 模型追问失败或没有可用模型时，自动回退到内置六问，保证流程不中断。
6. 追问 JSON 被截断时，会保留最后一个完整问题并继续，不会直接丢掉整份计划。

实测“二手书交易小程序”需求时，模型生成的问题包括交付对象、交易闭环、信用评价、聊天能力、书籍字段和校区范围；选择“课程答辩”和“线上下单+线下自提”后，最终提示词明确继承这两个回答。
