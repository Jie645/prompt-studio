| 测试模型 | DeepSeek `deepseek-chat` |

| 提示词版本 | 1.3.0 · 含执行契约 / 输出格式 / 必须覆盖 |
| 结果文件 | `模型执行测试结果.md` |

## 一、结论

改进后的提示词可以直接交给 AI 工作，不再是“给你一个写提示词的建议”。

本次用“AI 笔记应用 PRD”作为真实任务，模型按提示词产出了：

- 一句话结论
- 用户画像
- 核心流程与异常路径
- 功能优先级表
- 验收标准
- 假设与待确认项
- 验收自检

输出约 **1,622 字**，所有关键检查项均通过：

```text
用户画像: 通过
核心流程: 通过
功能优先级: 通过
验收标准: 通过
假设/待核实: 通过
验收自检: 通过
```

## 二、这次补强的执行契约

生成结果现在固定包含：

1. **执行契约**：说明什么时候直接开工；只有缺少会改变核心结论的信息时，才最多问 3 个问题。
2. **输入**：列出使用对象、材料和已确认信息。
3. **交付物**：明确主交付与附带交付，避免只输出框架。
4. **必须覆盖**：从用户需求中提取用户画像、流程、优先级、验收等项目，缺项视为未完成。
5. **输出格式**：固定为“最终交付物 → 假设与待确认 → 验收自检”。
6. **领域格式**：
   - 前端/后端：文件树、关键代码、运行命令、测试命令、错误分支；
   - 产品：用户画像、核心流程、功能优先级、验收标准、风险依赖；
   - 数据：指标口径、取数步骤、结论、置信度；
   - 客服/运营：分类、标准话术、升级条件、质检点。

## 四、仍需注意

- 这次验证的是 DeepSeek 模型；没有使用真实阿里云百炼账号做计费调用。阿里云路径已经通过本地 mock 验证协议和代理链路，实际使用仍需要正确的模型 ID、API Key 和接口权限。
- 真实模型的输出质量仍受模型能力影响；提示词已经消除了“只输出计划”“重复需求”“验收不可判定”这类模板问题。
- 建议用户在“添加模型”弹窗中先点“测试连接”，确认模型服务和代理都正常，再生成正式提示词。
