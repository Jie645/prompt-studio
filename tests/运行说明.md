# 回归测试运行说明

这套脚本是排查 Prompt Studio 时用的**完整回归用例**，直接针对 `src/` 里的源码跑。
改完代码请跑一遍，用来证明"没改坏，且把该修的修好了"。

## 依赖

只需要 **Node.js**（本项目零依赖，测试脚本也零依赖）。Windows 上用 `node` 即可。

## 脚本清单

| 文件 | 作用 |
| --- | --- |
| `run-all.mjs` | **一键跑全部**：起环境 → 跑 4 批用例（137 项）→ 收尾还原。日常只用这个。 |
| `test-regressions.mjs` | **B2 / B3 专项**：故障注入验证「配置损坏不丢数据」「密钥不上命令行」（8 项），需要单独跑 |
| `mock-upstream.mjs` | 模拟上游模型服务（被上面两个脚本自动拉起，也可单独起） |
| `test-api.mjs` | API 集成测试（53 项） |
| `test-extra.mjs` | 边界 / 并发 / 稳定性 + 共用模块单元测试（35 项） |
| `test-verify.mjs` | 协议细节与中文回归（7 项） |
| `test-front.mjs` | 注入最小 DOM 桩，驱动真实前端模块（42 项） |
| `browser-test.js` / `cmp.js` / `filetest.js` | 真实浏览器端到端脚本（需浏览器自动化工具） |
| `dpapi-probe.mjs` | 单独探测本机 DPAPI 加解密是否可用 |
| `基线-改动前.log` | 整改前的完整测试输出，用来对比改动后有没有退步 |

## 三个端口的分工

| 端口 | 角色 | 说明 |
| --- | --- | --- |
| 5199 | **模拟上游模型服务** | `mock-upstream.mjs`，冒充 DeepSeek/OpenAI。它能按系统提示词判断当前是"解析/撰写/评审/修订"哪个阶段并返回对应内容，还支持错误注入（401/500/断连）和 SSE 流式。 |
| 5190 | **被测的 Prompt Studio** | 跑 `src/` 里的源码，**不要直接拿正在用的那份正式程序测**。 |
| 5178 | 正式默认端口 | 测试不用它，避免和你在用的实例打架。 |


## 跑法

### 最省事：一条命令跑完全部

```bash
node tests/run-all.mjs            # 4 批共 137 项
node tests/test-regressions.mjs   # B2 / B3 专项 8 项（单独跑，见下）
```

`run-all.mjs` 会自动备份并清空 `src/data/profiles.json` → 起被测服务（**并清空 API Key 环境变量**）→ 起模拟上游 → 依次跑 4 个用例 → 结束子进程并还原数据文件。

> `test-regressions.mjs` 要**单独跑**，不要和 `run-all.mjs` 同时跑——它需要重启被测服务并篡改数据文件，两条线同时操作同一个 `src/data/` 会互相干扰。
> 它要高频轮询系统里的 `powershell.exe` 进程命令行，**耗时约 3–5 分钟**（`run-all.mjs` 只要 40 秒左右），请耐心等。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | 5190 | 被测服务端口（`run-all`） |
| `PORT2` | 5191 | 临时实例端口（`test-regressions`） |
| `MOCK_PORT` | 5199 | 模拟上游端口 |
| `KEEP` | — | 设为 1 则跑完**不还原** `src/data/profiles.json`（调试用） |

> ⚠️ **为什么要清空 API Key 环境变量**：如果本机设了 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`，
> 程序首次读取接口列表时会自动"铺种"出两条接口，界面上的"离线规则模式"用例（要求 0 个接口）
> 就会失败。这不是程序 bug，是测试环境干扰。`run-all.mjs` 已经处理好了；手工跑的话要自己注意。

### 手工分步跑（想单独调试某一批时用）

#### 1. 准备一份隔离的测试实例

```bash
cp -r src _run                # Windows: xcopy /E /I src _run
printf '{\n  "version": 1,\n  "profiles": []\n}\n' > _run/data/profiles.json
```

#### 2. 起模拟上游（一个终端，保持不关）

```bash
node tests/mock-upstream.mjs          # 默认 5199
# 或：MOCK_PORT=5199 node tests/mock-upstream.mjs
```

#### 3. 起被测服务（另一个终端，保持不关）

```bash
cd _run
PORT=5190 HOST=127.0.0.1 NO_OPEN=1 PROMPT_STUDIO_API_KEY= DEEPSEEK_API_KEY= OPENAI_API_KEY= node server.mjs
```

> Windows PowerShell：
> `$env:PORT=5190; $env:NO_OPEN=1; $env:DEEPSEEK_API_KEY=""; $env:OPENAI_API_KEY=""; node server.mjs`
> `NO_OPEN=1` 是防止测试时乱弹浏览器。

#### 4. 跑用例（第三个终端）

```bash
PS_ROOT="$PWD/_run" PS_BASE=http://127.0.0.1:5190 PS_MOCK=http://127.0.0.1:5199 \
  node tests/test-api.mjs
# 同理跑 test-extra / test-verify / test-front，也可省略 PS_* 用默认值
```

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `PS_BASE` | `http://127.0.0.1:5190` | 被测服务地址 |
| `PS_MOCK` | `http://127.0.0.1:5199` | 模拟上游地址 |
| `PS_ROOT` | 当前工作目录 | 被测项目根目录（含 `public/`），`test-front` / `test-extra` 用它定位源码 |


### 5. 可选：真实浏览器端到端

需要浏览器自动化工具（本次用的是 `agent-browser`）。页面地址默认 `http://127.0.0.1:5190`。

```bash
agent-browser open "http://127.0.0.1:5190/index.html"
agent-browser eval "$(cat tests/browser-test.js)"   # 完整用户流程
agent-browser eval "$(cat tests/cmp.js)"            # 多模型对比
agent-browser eval "$(cat tests/filetest.js)"       # file:// 直接打开模式
```

## 期望结果

- 各脚本会逐行打印 `PASS / FAIL 编号 名称`，脚本结尾打印统计。
- **改动前的基线**：`run-all.mjs` 137 项检查，通过 126、失败 11；`test-regressions.mjs` 8 项，通过 2、失败 6。
- 这 11 + 6 项失败**全部对应真实缺陷**（清单见 `01-整改任务书.md` 第五节），没有一项是测试桩自身问题——基线已归档在 `基线-改动前.log`。
- 你要做的是：**跑完只剩 0 项失败**，且原有 126 项通过项一项都不能变红（那才叫没改坏）。

## 已知的测试脚本自身局限（不是被测程序的 bug）

1. 这些脚本**不做用例隔离**：它们会往被测实例里写接口配置并删除，跑之前最好把 `_run/data/profiles.json` 清空。
2. `test-front.mjs` 的 DOM 桩是**手写最小实现**，`innerHTML` / `querySelectorAll` 只做有限模拟，涉及复杂 DOM 结构的断言可能失真。
3. `browser-test.js` 依赖页面已加载完成；如果刚 `open` 完立刻 `eval` 可能拿到空状态，建议 `open` 后稍等 1–2 秒。
4. `filetest.js`（`file://` 直接打开）在某些环境下浏览器 CDP 通道会中断，可能拿不到结果——这一项可以只按代码路径人工核对。

## 清理

```bash
# 关掉两个终端，或按端口找进程结束；然后删掉测试实例
rm -rf _run
```
