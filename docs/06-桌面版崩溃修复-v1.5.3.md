# 桌面版主进程崩溃修复（v1.5.3）

## 1. 现象

安装版 `Prompt Studio` 在「沟通补充 · 第 N 轮」弹窗操作期间，弹出系统级错误框：

```
Error
A JavaScript error occurred in the main process

Uncaught Exception:
AbortError: This operation was aborted
    at new DOMException (node:internal/per_context/dom-exception:53:5)
    at AbortController.abort (node:internal/abort_controller:391:18)
    at ServerResponse.<anonymous> (...\resources\app.asar\main.js:54:36)
    at ServerResponse.emit (node:events:530:35)
    ...
```

框体是模态的：**关掉之前主进程事件循环被阻塞**，页面没有任何响应；连续出现时只能强杀进程。

## 2. 根因

`desktop/main.js` 的本地代理把客户端断连当作「取消上游请求」的信号：

```js
const controller = new AbortController();
res.on("close", () => controller.abort());      // ← main.js:54
...
if (upstream.body) {
  Readable.fromWeb(upstream.body).pipe(res);    // ← 没有 error 监听
}
```

触发链条：

1. 页面在流式生成中途断开连接（关弹窗、切轮次、Esc、刷新、关窗口都会立即断开 `fetch`）。
2. `res` 的 `close` 事件触发 `controller.abort()`。
3. 上游响应体是 `ReadableStream`，被 abort 后以 `AbortError` 终止；`Readable.fromWeb()` 把它转成 Node 流并 emit `error`。
4. 该流接了 `.pipe(res)` 却没有 `error` 监听 → Node 判定为**未捕获异常**，Electron 主进程默认弹「A JavaScript error occurred in the main process」。

`try/catch` 兜不住，因为异常不在 `await` 表达式上，而是流对象异步 emit 的事件。

> 注意这条路径只在「已经拿到响应头、正在流式转发」时才触发；请求还没建立起连接时 abort，`await fetch` 的 reject 是能被 `catch` 接住的，所以该缺陷表现为偶发。

## 3. 修复内容（仅 `desktop/main.js`）

| 位置 | 修复 |
| --- | --- |
| 断连处理 | `res.on("close")` 里加 `clientGone` 标记；`abort()` 前先判 `signal.aborted`，并包 `try/catch` |
| 流式转发 | `.pipe(res)` 换成 `await pipeline(body, res)`，`body` 额外挂 `error` 监听主动 `destroy`；异常统一进 `catch` 消化 |
| 异常分类 | `AbortError` / `ABORT_ERR` / `ERR_STREAM_PREMATURE_CLOSE` 与「客户端已断开」一律静默返回，不再尝试写已关闭的 socket |
| 写失败 | 代理与静态资源响应都挂 `res.on("error", noop)`，客户端 EPIPE 不再冒泡 |
| 调用点 | `handleProxy(...)` 补 `.catch()`；`createServer` 增加 `clientError` 处理 |
| 主进程兜底 | 新增 `uncaughtException` / `unhandledRejection` 处理器，异常写入 `%APPDATA%\prompt-studio\error.log`（超过 512KB 轮转），**不再弹模态框**；`AbortError` 直接忽略 |

页面 `standalone/index.html` **本次未改动**，1.5.2 的页面行为完全保留。

## 4. 回归验证

同一进程内并排运行「1.5.2 旧实现」与「1.5.3 新实现」，上游为 60ms 一帧的慢速 SSE，客户端读到第 2 块数据后 `destroy`：

```
旧实现 uncaughtException: 1 [ 'AbortError: This operation was aborted' ]
新实现 uncaughtException: 0 []
PASS 缺陷已复现且已修复
```

错误名与截图完全一致，确认抓到的就是同一缺陷。

### 4.2 端到端：`qa/t16-electron-abort.mjs`

启动真实 Electron 主进程，直接打 `127.0.0.1:8787/api/proxy`：

| 用例 | 1.5.2 | 1.5.3 |
| --- | --- | --- |
| 正常 JSON 转发 | 200 + 内容正确 | 200 + 内容正确 |
| 上游 500 | 500 + 错误体透传 | 500 + 错误体透传 |
| 流式响应中途断开 ×3 | **主进程被错误框阻塞，代理不再响应，脚本 45s 超时（exit 124）** | 进程存活、代理继续服务、`error.log` 新增 0 字节（exit 0） |
