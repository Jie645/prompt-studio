## 二、硬约束（不许违反）

1. **不要改 `src/data/profiles.json` 的用途**：它是运行时用户数据，程序第一次启动会自己生成。你只可以改它的**读写逻辑**（B2 要改）和结构（若加字段需兼容旧文件）。

3. **`adapters.mjs` 是前后端共用的纯函数模块**：不许在里面引入 `window`/`document`/`fs`/`process` 之类的环境 API，否则浏览器端会崩。

5. **保持 API 路径不变**：`/api/health`、`/api/profiles`、`/api/profiles/<id>`、`/api/relay/<id>` 的路径和方法约定不要动（验收测试依赖它们）。

## 三、必修项（B1–B8，一条都不能漏）

### B1 🔴 「保存并测试」连点两次会重复创建同名接口

- **文件·位置**：`src/public/js/profiles.js` — `#pfTest` 事件处理器（约 37–40 行）、`saveForm(quiet)`（约 213–251 行）
- **现象**：在"新增接口"表单里点一次「保存并测试」，接口建好了；**再点一次，又建一条同名接口**。真实浏览器可复现。
- **根因**：`#pfTest` 调 `saveForm(true)`。`quiet === true` 时函数**既不关闭表单、也不把新建返回的 id 写回 `profileState.editingId`**。表单一直停留在"新增"状态，于是 `editing` 恒为 `null`，每次点击都走 `POST /api/profiles`。
- **期望修复**：`quiet` 分支也要把新建结果回写为"正在编辑该条"——`profileState.editingId = data.profile.id`，并同步 `#pfDelete` 的可见性、`#pfSave` 的文案（新增/保存共用一套 UI 状态更新逻辑最好抽出来）。
- **验收**：在新增表单里连点两次「保存并测试」→ 接口列表**只多出一条**。

### B2 🔴 `profiles.json` 损坏时静默丢数据，还会被自动覆盖

- **文件·位置**：`src/server.mjs` — `loadStore()`（约 156–162 行）、`seedFromEnv()`（约 189–203 行）
- **现象**：把 `profiles.json` 写坏（例如截断、断电写一半）后启动服务，**文件里的接口全部消失**，且被环境变量铺种的数据覆盖，全程没有任何日志、告警或备份。这是本次排查风险最高的数据安全问题。
- **根因**：`loadStore()` 的 `catch {}` 把"解析失败"等同于"没有配置"，返回空 store；紧接着 `GET /api/profiles` 会调 `seedFromEnv()` 并 `saveStore()` **写盘**，把原文件彻底覆盖。
- **期望修复**（三点都要）：
  1. 解析失败时**不要吞掉**：把坏文件 `rename` 成 `profiles.json.corrupt-<时间戳>` 备份，打一条醒目的中文日志，并让接口返回明确错误（而不是假装空配置）。
  2. **`GET` 不做写操作**：环境变量铺种挪到**服务启动时**执行一次，去掉读取接口的写副作用。
  3. `saveStore()` 写新文件前，把当前文件另存一份 `profiles.json.bak`。
- **验收**：写入一个截断的 `profiles.json`（内含 1 条 `p_real`）→ 启动服务 → **原文件被备份而非消失**，服务端日志有明确告警，`GET /api/profiles` 不返回"空列表"而是报错或返回原数据。

### B3 🔴 API Key 的明文（base64）会被拼进 PowerShell 命令行；探测失败还会静默降级成伪加密

- **文件·位置**：`src/server.mjs` — `runPowerShell()`（约 108–113 行）、`protectKey()`（约 125–133 行）、`revealKey()`（约 135–148 行）
- **现象**：`protectKey` 把明文 Key 的 base64 直接拼进命令行字符串传给 `powershell -Command`。**同一 Windows 账户下的任何进程都能读到别人的命令行**（本项目的 `uninstall.ps1` 自己就是用 `Win32_Process.CommandLine` 找进程的），也会进 ETW / 审计日志。base64 不是加密。
- **附带问题**：`dpapiAvailable()` 探测失败（PowerShell 被策略或 EDR 拦、`execFileSync` 抛 `EBUSY`/`ENOENT`）时会**静默降级**为 `scheme: "base64"`，界面上只有一行小字提"未加密"。
- **期望修复**：
  1. 改用 **stdin 传值**（`spawnSync("powershell", ["-NoProfile","-NonInteractive","-Command","-"], { input: ... })`），命令行里不再出现任何密钥/密文片段；或改用不依赖 PowerShell 的 DPAPI 调用方式。
  2. 探测失败时，`/api/health` 要明确上报当前加密方案，**页面顶部给一条显著提示**（"你的密钥当前未加密存储"），不能只藏在小字里。
  3. 保持兼容：已存在的 `dpapi` / `base64` 两种历史密文都要能正常解出来。
- **验收**：加密一次后，从 `Win32_Process.CommandLine` 里**读不到**任何形如 base64 的密钥片段；探测失败时接口返回的加密方案字段能反映真实状态，且前端有可见告警。

### B4 🔴 「自定义模板」协议遇到含引号/反斜杠的内容必定 500

- **文件·位置**：`src/public/js/adapters.mjs` — `renderTemplate()`（14–19 行）、`custom.body()`（约 168–182 行）
- **现象**：用户内容里只要出现 `"`、`\` 或 `{{...}}`，请求必定 500，报错还把内部 JSON 解析位置回显给用户（`Expected ',' or '}' ... at position 57`）。
- **根因**：把 `{{user}}`、`{{system}}` 等**原样字符串替换**进一段 JSON 文本，然后 `JSON.parse`。内容一含特殊字符就把模板结构撑坏。同一内容走「OpenAI 兼容」协议完全正常。
- **期望修复**：
  1. `renderTemplate` 对**字符串值**先做 JSON 转义再插入（例如拼进 `"..."` 位置时用 `JSON.stringify(v).slice(1, -1)`）；或改成"先构造对象再序列化"的思路。
  2. 给 `adapter.body` 加 `try/catch`，模板渲染/解析失败时返回 **400 + 中文提示**（如"请求体模板不是合法 JSON，检查一下 {{user}} 周围的引号"），不要 500，也不要回显内部解析位置。
- **验收**：`user = 请写"你好"这两个字` 走自定义模板 → **不再 500**，上游收到的请求体里内容完整、JSON 合法。

### B5 🟠 「已回退到第 N 轮」的提示会被下一条日志瞬间覆盖

- **文件·位置**：`src/public/js/app.js` — 迭代停止逻辑（约 336–349 行）
- **现象**：择优回退确实生效了（正文变回高分那版），但用户永远看不到"已回退"，因为紧接着的"已完成 N 轮。停止原因：…"把上一行冲掉了。
- **根因**：`log()` 是**单行 `textContent` 赋值**，不是日志流；先写的回退提示被后写的覆盖。
- **期望修复**：把日志改成**追加式列表**（保留历史若干条，可滚动）；或者最少做到"回退信息合并进最后那条摘要"，让回退这件事对用户可见。
- **验收**：跑一次会触发回退的深度模式 → 页面上能同时看到"已回退到第 1 轮（7.0 分）"和"已完成 2 轮"两条信息。

### B6 🟠 回退之后「自评徽标」与展示的正文对不上

- **文件·位置**：`src/public/js/app.js` — 回退逻辑（约 337–348 行）、`renderScoreChip()`（约 912–934 行）、`buildExportDoc()`（约 468 行）
- **现象**：正文是第 1 轮（7.0 分）那版，但工具条徽标写着"自评 6.0 · 2 轮"——因为徽标和导出文档读的都是 `state.critique`，而 `state.critique` 还停留在**最后一轮（更差那轮）**。
- **期望修复**：`state.rounds` 里**每轮一起保存该轮的 critique**；回退时把 `state.critique` 同步替换成被保留那一轮的评审，徽标、导出文档保持一致。
- **验收**：回退发生后，徽标显示的分数轮次 == 正文对应那一轮的分数；导出的文档里模型名/评分与正文一致。

### B7 🟠 以前设过的 temperature / max tokens 永远清不掉

- **文件·位置**：`src/public/js/profiles.js` 约 221–224 行（用 `undefined` 表示空）→ `src/server.mjs` `sanitizeProfile()` 约 211 行的 `{ ...旧 params, ...新 params }` 合并
- **现象**：设 temperature = 0.3 → 清空输入框再保存 → **仍然是 0.3**。
- **根因**：`JSON.stringify` 会丢掉值为 `undefined` 的键，服务端看到的是"这次没提交这个字段"，于是沿用旧值。
- **期望修复**：用显式 `null` 表示"清除"（服务端见到 `null` 就从 params 里删掉该键）；或前端提交完整的 params 快照、服务端整体替换而不是合并。顺便给数字做范围校验（见 L10）。
- **验收**：设 0.3 → 清空保存 → 配置里 temperature 消失，不是残留 0.3。

### B8 🟠 「自定义模板」的变量名范围与变量页不一致，中文变量静默失效

- **文件·位置**：`src/public/js/adapters.mjs` 第 15 行（`[a-zA-Z0-9_]+`）vs `src/public/js/prompt-engine.mjs` 第 505 行左右的变量提取正则（含中文、`.`、`-`）
- **现象**：`{{活动名称}}`、`{{user.name}}` 在变量页能识别、能填值，但走自定义模板协议时**不会被替换**，原样发到上游，且没有任何提示。两套正则各写各的。
- **期望修复**：把变量正则抽成一份共用常量（建议放 `adapters.mjs` 或新建 `vars.mjs`，两边 `import`），统一支持中文变量名与点/短横线。
- **验收**：`{{活动名称}}` 走自定义模板 → 请求体里被正确替换。

## 附：设计意图（避免你"修错方向"）

- `state.rounds`、`state.critique` 这套设计本意就是"每轮都记分、最后挑最高的那一版"——B5/B6 是这个设计没实现完，**不要为了消除 bug 把"择优回退"功能删掉**。
- 密钥不落明文、不回传浏览器是**刻意设计**，B3 是要把实现路径换成安全的，不是取消加密。
- `adapters.mjs` 前后端共用是**刻意设计**，改的时候注意它必须保持环境无关（纯函数）。
- 离线规则模式（没有 API Key 时也能出内容）是**刻意设计**，别因为它"看起来像 fallback"就删掉。
